# PlyForge

**Generate 1:1 ply cutting templates for composite layups by non-planar slicing of a mold or finished-part STL.**

PlyForge slices an STL file into **non-planar layers** starting from the **top and bottom surfaces** and working **inwards** toward the middle. Each layer outline is exported as a **PNG** image that can be printed at 100% and used directly as a ply template — for glass-fiber or carbon-fiber layup, or for building a two-part mold of a hydrofoil wing.

Both axes always start at 0: all coordinates are shifted by the mesh's minimum on each axis before plotting, so an object spanning `X = 170…200` is shown as `0…30`.

I use this script to get the number and sizes of the glass/carbon-fiber layers needed for hydrofoil wing molds.  
I used AI to generate this script and almost everything else in this repo except for the stabilizer model.  
The model and the corresponding mold can be found on OnShape: https://cad.onshape.com/documents/66d331a9fccd4acec3b34d53/w/03f3d3d59bcf4329b3c8e583/e/922d49efb1a5102df9fa174c  
In [layers](layers) there are example images generated by this script when run with the default parameters and the provided stabilizer model.

## How it works

1. The STL is loaded and its bounding box is determined.
2. A regular grid over the XY footprint is created (resolution controlled by `--resolution`).
3. Vertical rays are cast through every grid point to obtain the **top** and **bottom** Z of the solid at each `(x, y)` — i.e. two height fields `top(x, y)` and `bot(x, y)`.
4. Local surface normals are approximated from the gradient of these height fields, giving `cos(theta)` for each point.
5. Layers are generated from both ends toward the middle:
   - **From the top:** offset downward along the surface normal by `k * h`, where `h` is the layer height.
   - **From the bottom:** offset upward along the surface normal by `j * h`.
6. Each layer's outline is the contour where the offset surface just touches the opposite side.
7. The contours are projected onto the XY plane and rendered as a PNG.

Because the offsets are measured along the surface normal, this approximates **constant layer thickness** on curved surfaces, rather than a simple horizontal cut.

## Quick start
Create a virtual env with python3.8 or higher and install the dependencies in requirements.txt.

```bash
python plyforge.py stabilizer.stl
```

This produces PNGs in `./layers/` using default settings:

- 0.2 mm layer height
- 300 grid resolution
- 200 DPI
- 1:1 print scale
- 5 mm labeled step on both axes
- Reference outline enabled, reference layer = 1

## Command-line options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `stl` | positional | — | Path to the input STL file (e.g. `stabilizer.stl`). |
| `--layer-height` | float | `0.2` | Nominal layer thickness in millimeters, measured along the surface normal. |
| `--out-dir` | string | `layers` | Output directory for PNG files. Created if it does not exist. |
| `--resolution` | int | `300` | Number of grid samples along the longer XY axis for ray casting. Higher = smoother outlines, slower. Reasonable range: 200–600. |
| `--dpi` | int | `200` | Pixel density of the PNGs. Physical print size is **unaffected** by DPI (see [Print scale](#print-scale-11-mm-on-paper)). |
| `--print-scale` | flag | on | Render at 1:1 physical scale so 1 mm on the model = 1 mm on paper at 100%. |
| `--no-print-scale` | flag | — | Disable 1:1 print scale; image is fixed at 10 inches wide with equal aspect ratio instead. |
| `--label-step-x` | float | `5.0` | Labeled tick spacing on the X axis, in mm. Set to `0` for auto (~20 labels, snapped to multiples of 5 mm). |
| `--label-step-y` | float | `5.0` | Labeled tick spacing on the Y axis, in mm. Set to `0` for auto. |
| `--reference` | flag | on | Draw the reference layer outline on every layer image (light-blue dashed). |
| `--no-reference` | flag | — | Disable the reference layer outline. |
| `--reference-layer` | int | `1` | Which layer to use as the reference, counted outward from the surface. `1` = outermost layer. Only meaningful when `--reference` is enabled. |

## Examples

**Default run** — 0.2 mm layers, reference outline on, reference layer = 1, 5 mm labels:

```bash
python plyforge.py stabilizer.stl
```

**Higher quality** — finer grid, higher DPI, custom output directory:

```bash
python plyforge.py stabilizer.stl \
    --layer-height 0.2 \
    --resolution 500 \
    --dpi 300 \
    --out-dir ./slices/stabilizer
```

**Custom label steps** — 10 mm on X, 2.5 mm on Y:

```bash
python plyforge.py stabilizer.stl \
    --label-step-x 10 --label-step-y 2.5
```

**Auto label step on X, 5 mm on Y**:

```bash
python plyforge.py stabilizer.stl \
    --label-step-x 0 --label-step-y 5
```

**No reference outline**:

```bash
python plyforge.py stabilizer.stl --no-reference
```

**Reference = the 3rd layer from each surface**:

```bash
python plyforge.py stabilizer.stl --reference-layer 3
```

**Fixed 10-inch-wide image instead of 1:1 print scale**:

```bash
python plyforge.py stabilizer.stl --no-print-scale
```

**Coarse preview** — fast, lower resolution:

```bash
python plyforge.py stabilizer.stl \
    --resolution 150 --dpi 120 --out-dir ./preview
```

## Output files

Filenames use the human-facing layer number, starting at `1` for the outermost layer of each side:

```
layers/
├── top_0001.png      # "Top layer 1"    — outermost top layer
├── top_0002.png      # "Top layer 2"
├── top_0003.png      # "Top layer 3"
├── ...
├── bottom_0001.png   # "Bottom layer 1" — outermost bottom layer
├── bottom_0002.png   # "Bottom layer 2"
└── ...
```

The number of layers produced depends on the maximum thickness of the object along Z and the chosen `--layer-height`. The two sides meet in the middle; the script stops generating layers once `2 * (i+1) * h >= max_thickness`.

If a requested layer lies beyond the solid on one side, it is skipped for that side (with a warning printed to the console).

## How each layer is computed

For a layer `k` from the top (1-based, `k = 1` is the outermost):

```
F_k(x, y) = top(x, y) - k * h * cos_top(x, y) - bot(x, y)
```

The **outline** of the layer is the **zero contour** of `F_k`:

- Where `F_k > 0`, the offset surface is still above the bottom of the solid — part of this layer.
- Where `F_k < 0`, the offset would have passed through the bottom — outside this layer.
- `F_k = 0` is the boundary.

Symmetric for the bottom side, using `cos_bot`.

Because `cos_top = 1 / sqrt(1 + |∇top|²)`, a vertical wall gives `cos_top = 0` (offset in Z = 0), a flat top gives `cos_top = 1` (offset in Z = h), and sloped surfaces fall in between. That is the essence of normal-offset slicing.

## Reading the PNGs

Each image contains:

- **White background.**
- **Black solid line** — the outline of the current layer, projected onto XY.
- **Light-blue dashed line** (optional) — the reference layer outline (by default the outermost layer of the same side). Drawn underneath the current outline.
- **5 mm dotted minor grid** — fine reference grid at 5 mm intervals, always on.
- **Darker dashed major grid** — at the labeled tick spacing.
- **Labeled ticks** — placed at the step configured by `--label-step-x` / `--label-step-y` (default 5 mm). X labels are rotated 45° to avoid overlap.
- **Equal aspect ratio** — 1 mm in X equals 1 mm in Y on screen.
- **Title** — `Top layer N` or `Bottom layer N`.
- **Axis labels** — `X (mm)` and `Y (mm)`. All text is 7 pt.

Every image uses the **same coordinate frame** (the mesh's XY extent anchored at 0), so you can flip through the images and compare directly.

---

## Axis origin and scaling

The script shifts every coordinate by the mesh's minimum on each axis before plotting. This means:

- **The X axis always starts at 0**, regardless of where the mesh sits in world coordinates.
- **The Y axis always starts at 0**, for the same reason.

For example, if the mesh's bounding box is `X = 170…200`, `Y = 40…90`, then the images will show:

- X axis from `0` to `30`
- Y axis from `0` to `50`

Both the current layer outline and the reference outline are shifted by the same amount, so they stay aligned. There is no padding added around the object, so the plot region equals the mesh's real XY extent. This is what makes the 1:1 print scale work cleanly.

---

## Print scale (1:1 mm on paper)

By default (`--print-scale`), each PNG is rendered so that **1 mm on the model equals 1 mm on paper** when printed at 100%.

This is achieved by:

1. Computing the plot region size in millimeters from the mesh's XY extent (no padding).
2. Converting to inches (`mm / 25.4`).
3. Reserving fixed margins in inches for the tick labels, axis labels, and title:
   - left `1.6 in`, right `0.4 in`
   - bottom `1.4 in`, top `0.7 in`
4. Placing the axes at an explicit position using `fig.add_axes([...])` so the plot region occupies exactly the real-world size, independent of the margins.
5. Enforcing `ax.set_aspect("equal")`, which is already satisfied by the axes rectangle.

**DPI does not change the printed size.** It only controls pixel density:

| `--dpi` | Typical pixel width for a 100 mm part |
|---------|----------------------------------------|
| 150 | ~700 px |
| 200 | ~950 px |
| 300 | ~1400 px |
| 400 | ~1900 px |

Warnings are printed if:

- The plot region is very small (< 0.5 in on either side) — consider `--no-print-scale`.
- The figure exceeds 50 in on either side — consider `--no-print-scale` to save time and disk.

To revert to a fixed 10-inch-wide image with equal aspect ratio:

```bash
python plyforge.py stabilizer.stl --no-print-scale
```

## Label steps and grid

Two layers of grid are always drawn:

| Grid | Spacing | Purpose |
|------|---------|---------|
| Minor | **5 mm**, always | Fine visual reference for measuring |
| Major | `--label-step-x` / `--label-step-y` | Labeled ticks; slightly darker line |

`--label-step-x` and `--label-step-y` accept any positive float. Non-integer steps are allowed:

```bash
--label-step-x 2.5    # every 2.5 mm
--label-step-y 25     # every 25 mm
```

Set either to `0` to fall back to an auto step that targets approximately 20 labels on that axis, always snapped to a multiple of 5 mm:

```bash
--label-step-x 0
```

If the step is very small relative to the object, tick labels may crowd. In that case:

- Increase `--dpi` to spread the labels over more pixels.
- Increase `--label-step-x` / `--label-step-y` to a larger value.
- Or leave the step at 0 to let the auto logic handle it.

The minor grid spacing (5 mm) is not configurable at the CLI; edit the two `MultipleLocator(5)` calls in `write_png` if you want to change it.

## Reference outline

Every layer image can include an **outline of a reference layer** as a light-blue dashed line underneath the current layer.

- Default: the **outermost layer of the same side** (top layer 1 on top images, bottom layer 1 on bottom images). This is a useful visual anchor to see how the current layer sits inside the outer silhouette.
- Change which layer is used with `--reference-layer N`. `N = 1` is the outermost layer, `N = 2` is one layer inward, and so on.
- Disable entirely with `--no-reference`.

If the requested reference layer lies beyond the solid on that side, a warning is printed and the reference is omitted for that side.

## Tuning tips

**Resolution.** The default `--resolution 300` is a good compromise. Increase to 400–600 for smoother outlines on fine detail; decrease to 150–200 for a quick preview. Ray casting is the dominant cost, and it scales roughly with `resolution²`.

**Layer height.** The script does not enforce a minimum or maximum — 0.2 mm is fine, 0.05 mm will produce many layers and take longer to render, 1 mm will produce very few. On very thin objects, `2 * h` may exceed the maximum thickness and only one side will produce a layer (or none). Check the console output.

**DPI.** 200 is usually enough for on-screen viewing. 300–400 for printing. Above 400 makes files large without much visible benefit because the outline stroke width is fixed in points.

**Reference layer.** Setting `--reference-layer 2` or `3` can be useful if the outermost layer is very small (e.g. the object narrows near the top) and does not give a useful overall silhouette.

**Smoothing.** The height fields are smoothed with `gaussian_filter(..., sigma=1.5)`. Very faceted meshes may still show small stair-step artifacts in the contours. If that happens, edit `sigma=1.5` in `build_height_fields` to `2.0` or `2.5`.

**Margins.** If you change `FONT_SIZE`, you may need to adjust `MARGIN_LEFT_IN` / `MARGIN_BOTTOM_IN` at the top of the script to keep the axis labels from overlapping the plot region.

## Troubleshooting

**"Mesh could not be loaded or is empty."**
The STL is empty, inverted, or in a format `trimesh` cannot parse. Try loading it in a viewer first, or use `trimesh.load(..., force='mesh')`.

**"No ray hits — mesh may be empty or inverted."**
Every vertical ray missed the mesh. Check that the mesh has non-zero Z extent and that its normals are not all flipped in a way that confuses `trimesh.ray`. Some scanners produce shells that need `mesh.fix_normals()` first.

**Output looks sheared or mirrored.**
The script assumes Y increases upward in the PNG. If your model uses a left-handed coordinate system or is upside-down, the projection will look flipped. This is cosmetic — the geometry is correct. Rotate the mesh before slicing if you want a specific orientation.

**Numbers on the axes overlap.**
Increase `--dpi`, or increase `--label-step-x` / `--label-step-y`. The 5 mm minor grid stays the same regardless.

**Some layers have very small or empty outlines.**
Normal. Near the top and bottom of a curved object, the outermost layers may have a tiny footprint, and layers near the middle may be empty when the object is thin. The script skips empty layers and prints a `no contours` message.

**Very slow on large meshes.**
Ray casting is O(resolution²). Drop to `--resolution 200` for a first pass, and only increase once you are happy with the layer height and other options.

**"warning: plot area is very small" / "warning: figure is very large".**
The 1:1 print scale is producing an image that may be impractical. Use `--no-print-scale` for a fixed 10-inch-wide image instead.

## Limitations

- **Only top and bottom surfaces.** For each grid column, only the topmost and bottommost ray hits are used. Objects with internal cavities or multiple disjoint solids along the same vertical line will lose the interior shells.
- **No true 3D intersection.** The layers are found as **contours of a height field**, not as intersections of two arbitrary meshes. This is a good approximation for objects that are functions of `(x, y)` (i.e. no overhangs or undercuts in the usual slicing sense).
- **No G-code.** The output is a set of PNG images for visualization and template cutting, not a toolpath.
- **No collision checking.** Nothing here accounts for nozzle geometry or printer kinematics.
- **Not constant-thickness in the strict sense.** Normal-offset on a height field is a first-order approximation of geodesic offsetting; on strongly curved surfaces the actual thickness will vary slightly from `h`.

## When to use a dedicated non-planar slicer

PlyForge is intended for:

- Generating ply templates for composite layup.
- Visualizing how non-planar layers would look on a mold or finished part.
- Producing analysis or documentation images.
- Prototyping curved-layer geometry before committing to a printer workflow.

For actual **printing** with non-planar toolpaths (e.g. printing the mold itself), use:

- **IceSL** — stable, curved-layer support, mature UI.
- **S4 Slicer** — transformation-based, produces very long continuous non-planar paths, designed for 4-axis hardware.
- **RotBotSlicer** — transforms G-code from a standard slicer into non-planar paths.
- **COMPAS Slicer** — Python library for research; supports true curved slicing via scalar fields.

These tools handle collisions, extrusion, toolpath planning, and machine-specific constraints, none of which PlyForge attempts.
